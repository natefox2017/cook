# 用户流程

## Flow A：第三方 App 一键收藏

1. 用户在 TikTok / Instagram / YouTube / 小红书 / 抖音 / Bilibili / Safari 等看到食谱。
2. 点击系统分享。
3. 选择 Cook。
4. Share Extension 接收 URL/文本/附件。
5. 显示简短反馈：“已收下，正在整理”。
6. 请求立即结束，用户回到原 App。
7. 后台创建 import job 并异步解析。
8. 完整结果自动进入食谱库。
9. 不完整结果进入食谱库，同时标记“待完善”。

禁止在第 4-6 步：
- 等待完整 AI 解析
- 选择食谱册
- 修改菜名
- 确认所有食材
- 强制打开主 App

## Flow B：App 内主动导入

主入口“添加”：
1. 粘贴链接
2. 截图/拍照
3. 其他方式
   - 粘贴文字
   - PDF/相册
   - 手动创建

默认优先级必须体现“自动导入优先，手动录入兜底”。

## Flow C：待完善

只有存在实质不确定性时出现。

示例：
- “糖：适量”可以直接保存，不强制确认。
- “画面疑似加入生抽，但无文字/语音证据”应标记来源与低置信度。
- 完全缺失关键步骤时进入待完善。

待完善页只呈现需要用户决定的字段，不重复展示整张表单。

## Flow D：做饭

食谱详情 → 开始烹饪：
- 大字体单步骤
- 本步骤关联食材
- 上一步 / 下一步
- 明确时间可一键启动单个计时器；模糊时间保留原文
- 防止屏幕快速休眠（遵循平台能力和用户设置）
- 始终可查看完整食材表

## Flow E：购物

食谱详情 → 加入购物清单：
- 支持按份量添加；未知原份量先按原量添加，不编造份量
- 相同规范化食材可合并
- 无法安全换算的单位不强行相加
- 用户可手工勾选/编辑

## Flow F：导入失败降级

禁止只显示“导入失败”。

示例：
- 已获取标题和 7 个食材，但缺少步骤 → 允许保存草稿 + 添加截图完善。
- 私有/登录墙内容 → 保留来源，提示用户添加截图或文字。
- 视频无法解析 → 尝试 Caption/网页/音频/关键帧后，给出已获得的部分结果。

## Flow G：整理（D1 已确认）

分享收下后直接出现在全部食谱；没有册归属时出现在未分类。用户之后创建食谱册并关联食谱；喜欢可独立切换。将同一食谱关联两册后修改一次，应在两册看到同一结果；移除一册关联或删除册，食谱与喜欢标记保留。不在分享扩展增加整理步骤。

## Flow H：离线购物与烹饪验收

联网保存食谱和购物清单 → 飞行模式 → 终止并重开 App → 搜索并打开食谱 → 做饭/查看原来源文本 → 加入购物 → 勾选、编辑、自定义增删 → 终止并重开 → 更改仍在 → 联网补传 → 无重复条目或静默丢失。分别覆盖安全合并数量和不可换算单位；未缓存图不阻止文本阅读。离线分享输入重开仍在队列，联网只产生一次导入。

## Flow I：份量与计时验收（D2 已确认）

2 人份 100g + 盐适量改 4 人份 → 200g + 盐适量，步骤时间和温度原值保留 → 加入购物使用该份量快照 → 再改食谱当前份量不偷偷改已加入条目。原份量未知时无法按人数自动换算。明确 5 分钟步骤启动计时 → 切步/锁屏/重开 → 剩余时间符合真实时间；拒绝通知仍能前台查看、暂停和取消。没有明确时长不能凭 AI 猜一个计时。

## Flow J：首次云导入（D4 已确认）

首次启动进入食谱库与可跳过的导入教学 → 首次云解析前建立账户 → 返回导入上下文，不丢来源 → 后续分享直接收下。会话过期/离线先可靠本地入队，下次主 App 完成登录再补传；首版不引入匿名绑定流程。

## Flow K：食谱导出（D3 已确认）

用户主动导出 → 生成包含数量/文件清单的导出包 → 用户保存到系统文件位置 → 脱离 Cook 打开 HTML 可读食材、步骤、来源，解析 JSON 可核对册关联/喜欢/待完善状态 → 缺媒体在清单列明。导出失败保留数据并允许重试；不把“导出完成”当作“可恢复备份验证通过”。

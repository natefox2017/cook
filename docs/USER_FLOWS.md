# 用户流程

## Flow A：第三方 App 一键收藏

1. 用户在 TikTok / Instagram / YouTube / 小红书 / 抖音 / Bilibili / Safari 等看到食谱。
2. 点击系统分享。
3. 选择 Cook。
4. Share Extension 接收 URL/文本/附件。
5. 显示简短反馈：“已收下，正在整理”。
6. 请求立即结束，用户回到原 App。
7. 后台创建 import job 并异步解析。
8. 完整结果自动进入食谱库。
9. 不完整结果进入食谱库，同时标记“待完善”。

禁止在第 4-6 步：
- 等待完整 AI 解析
- 选择食谱册
- 修改菜名
- 确认所有食材
- 强制打开主 App

## Flow B：App 内主动导入

主入口“添加”：
1. 粘贴链接
2. 截图/拍照
3. 其他方式
   - 粘贴文字
   - PDF/相册
   - 手动创建

默认优先级必须体现“自动导入优先，手动录入兜底”。

## Flow C：待完善

只有存在实质不确定性时出现。

示例：
- “糖：适量”可以直接保存，不强制确认。
- “画面疑似加入生抽，但无文字/语音证据”应标记来源与低置信度。
- 完全缺失关键步骤时进入待完善。

待完善页只呈现需要用户决定的字段，不重复展示整张表单。

## Flow D：做饭

食谱详情 → 开始烹饪：
- 大字体单步骤
- 本步骤关联食材
- 上一步 / 下一步
- 时间可一键启动计时
- 防止屏幕快速休眠（遵循平台能力和用户设置）
- 始终可查看完整食材表

## Flow E：购物

食谱详情 → 加入购物清单：
- 支持按份量添加
- 相同规范化食材可合并
- 无法安全换算的单位不强行相加
- 用户可手工勾选/编辑

## Flow F：导入失败降级

禁止只显示“导入失败”。

示例：
- 已获取标题和 7 个食材，但缺少步骤 → 允许保存草稿 + 添加截图完善。
- 私有/登录墙内容 → 保留来源，提示用户添加截图或文字。
- 视频无法解析 → 尝试 Caption/网页/音频/关键帧后，给出已获得的部分结果。

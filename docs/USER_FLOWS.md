# 用户流程

## Flow A：第三方 App 一键收藏

1. 用户在 TikTok / Instagram / YouTube / Safari 等公开来源，或其他用户实际有权访问的平台看到食谱。**这是目标用户场景，不代表当前 Worker 能抓取所有网站/视频**；登录/版权受限来源不绕过。
2. 点击系统分享。
3. 选择 **Recipe Pals**（支持来源以已安装 Share Extension 的 activation 和实际平台权限为准）。
4. Share Extension 接收 URL/文本/附件。
5. 显示简短反馈：“已收下，正在整理”。
6. 请求立即结束，用户回到原 App。
7. 后台创建 import job 并异步解析。
8. 完整结果自动进入食谱库。
9. 不完整结果进入食谱库，同时标记“待完善”。

禁止在第 4-6 步：
- 等待完整 AI 解析
- 选择食谱册
- 修改菜名
- 确认所有食材
- 强制打开主 App

## Flow B：App 内主动导入

主入口“添加”：
1. 粘贴链接
2. 截图/拍照
3. 其他方式
   - 粘贴文字
   - PDF/相册
   - 手动创建

默认优先级必须体现“自动导入优先，手动录入兜底”。

## Flow C：待完善

只有存在实质不确定性时出现。

示例：
- “糖：适量”可以直接保存，不强制确认。
- “画面疑似加入生抽，但无文字/语音证据”应标记来源与低置信度。
- 完全缺失关键步骤时进入待完善。

待完善页只呈现需要用户决定的字段，不重复展示整张表单。

## Flow D：做饭

食谱详情 → 开始烹饪：
- 大字体单步骤
- 本步骤关联食材
- 上一步 / 下一步
- 时间可一键启动计时
- 防止屏幕快速休眠（遵循平台能力和用户设置）
- 始终可查看完整食材表

## Flow E：购物

食谱详情 → 加入购物清单：
- 支持按份量添加
- 相同规范化食材可合并
- 无法安全换算的单位不强行相加
- 用户可手工勾选/编辑

## Flow F：导入失败降级

禁止只显示“导入失败”。

示例：
- 已获取标题和 7 个食材，但缺少步骤 → 允许保存草稿 + 添加截图完善。
- 私有/登录墙内容 → 保留来源，提示用户添加截图或文字。
- 视频无法解析 → 尝试 Caption/网页/音频/关键帧后，给出已获得的部分结果。

## Flow G：导出食谱

入口：Profile → Export Data 或 Settings → Data & Privacy → Export Data，两个入口使用同一格式与结果反馈。

1. 选择 **Recipes (JSON)**：导出 `recipepouch.recipes` v1，可携带菜名、份量、原始食材用量、步骤、备注、来源、Favorites、Collections 与归属。
2. 选择 **Recipes (HTML)**：同一食谱文本的独立离线可读 HTML；所有用户输入经过转义，不依赖外部脚本或媒体资源。
3. 可选 **All Local Library Data (JSON)**：保留原本的完整本地库快照，额外包括购物、周计划与本地设置；它不是可恢复的设备备份。
4. 调用 iOS 系统文件保存；完成后提示保存的文件名，取消时不误报失败，写入/权限失败时显示错误。

上述导出均不包含会话凭据、服务端密钥或照片附件；当前版本不支持把导出文件重新导入为 App 备份。源文本中模糊/缺失的用量保持原样；导出不改动本地库。

## Flow H：AI 对话生成食谱（**规划 #238–#241，尚未上线**）

1. Share Extension 只做可靠接收与短反馈，**不等待模型生成**。
2. 后端优先从可访问网页结构化信息/描述/字幕获取 evidence，媒体只在合法许可和配置批准后解析；系统保留来源/作者及缺失字段。
3. 已充分提取的信息可直接作为私有食谱保存；存在关键缺口时只询问 1–3 个可回答问题，也可跳过/保存草稿。
4. **忠实提取**保留不确定性，**AI 灵感创作**必须把推断标为 AI 建议。用户预览、更正和确认保存的版本有更高优先级，后台重试不能覆盖。
5. AI 食材替换/份量修改返回结构化前后差异，用户可拒绝/应用/保留原版。多道菜时先选择候选；不把食材拼成一道。
6. #250 负责真实受控 staging；只有选择进入发布的功能在 #251 获取端到端证据。

## Flow I：用户自主分享单道食谱（**规划 #242–#244，尚未上线**）

1. Recipe Detail 默认 Private。用户点 **Share Recipe** 并明确同意允许公开的字段/图片、版权/原来源范围；未授权第三方原图/步骤不能自动公开。
2. 后端生成可撤销、不可枚举的只读快照与 HTTPS 分享链接（不是用户整个私人食谱库）。用户可停止分享或显式更新发布版本。
3. 未安装 App 的访客无需注册也能看被授权的完整做菜步骤；适当展示 App Store CTA，**不强制安装才能阅读**。
4. 可复制可点击链接、经系统 share sheet 发短信/邮件/社交软件，或导出食谱长图；长图底部有二维码/可读短链接，但二维码是**辅助**，不是唯一入口。
5. 撤销/删除后 Web/预览/海报地址不再暴露私人内容。域名、版权、Universal Link 在 #250/#251 验收。

## Flow J：邀请与可选后续奖励（**规划 #245、#246**）

分享者可以看到去标识化的访问/下载按钮点击量，但单凭 App Store 跳转**无法确定具体用户安装**。只有受邀用户自愿输入/确认邀请码，且通过身份/反作弊验证后，才记录真正的邀请关系。奖励是另行审批的 P2，当前不发放或承诺订阅权益。
